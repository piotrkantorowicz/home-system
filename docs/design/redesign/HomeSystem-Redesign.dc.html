Build review

Przegląd wdrożenia · what landed well, what to change next — with redesigned controls below

What's good — keep it
  • The token layer is right. Semantic names (--color-water, text-text-2, border-border-strong) are used consistently instead of raw hexes, and both themes resolve from one place.
  • Real primitives, not copies. Ring, MacroBar, MetricTile, StatusPill, SegmentedControl, Skeleton, EmptyState, Banner and Pagination each ship as their own module — the Control Kit page paid for itself.
  • Every screen has loading and empty states. Skeletons match the real geometry and empty states carry a CTA.
  • The module registry is the best decision in this build. basePath, navItems, routes and per-module i18n namespaces mean a second module needs no shell changes.
  • Bilingual copy is fully wired through i18n rather than hard-coded — nothing to redo when you add a third language.
  • The redundant header search is already gone. Agreed — it was a global field that searched nothing. Two leftovers: delete the stale search_placeholder: "Search food, recipes…" key, and note that the header in this document now shows the replacement instead — a ⌘K command trigger, per 2c.
What to change — in priority order
  1. The rail can't survive a second module. It flattens every module's navItems into one unlabeled column of icons — with two modules you can't tell which item belongs where. Fix in 2a.
  2. Six routes are unreachable from the rail. Only Dashboard, Calendar, Products and Recipes are registered; Hydration, Nutrition, Import, Profile, Preferences and Control Kit exist but you must type the URL. Also fixed in 2a.
  3. Water can't be un-added where you add it. The entries list does have a delete, but a mistap on a glass sends you hunting down the page. Fix in 2b.
  4. One pending write disables every quick-add. disabled={isPending} greys all three buttons; only the pressed one should show progress.
  5. Custom amount is three controls for one number — two 42px inputs plus a button, permanently expanded. Fix in 2b.
  6. The launcher page is a door in front of a door. "Welcome back" plus a single module card costs a click and teaches nothing. Fix in 2c.
  7. Two water widgets, two geometries. The dashboard card draws 44px glasses, Hydration draws 54px, and the dashboard's "Custom" navigates away. Extract one GlassRow and share it.
  8. "Remaining" goes negative without saying so. The hero swaps to over-budget, but the stat strip still prints a bare number — give it the − sign and --fat colour.

Why two tiers

The 64px rail answers "which product am I in" and holds one icon per registered module plus a "+" for what's next. The 216px panel answers "where in it" with real text labels — which is what lets a module carry ten destinations instead of four. Section headings (Plan / Library / Track) come from a new optional group field on each navItem; items without one fall into an unlabeled first group, so existing modules keep working.

Cost of the panel

280px total vs 76px today. Collapsible: a chevron at the module heading folds the panel to icons-only (64+56px) and the choice persists. Below 768px both tiers disappear — the module rail becomes a switcher in the header and sections become the bottom tab bar, exactly as the mobile mock already shows.

Registry change

Register all ten diet-planner destinations in navItems, each with group and an optional Badge (the shopping-list count, the inbox dot). Control Kit stays out of the panel — keep it dev-only behind a flag. The shell then renders nav entirely from the registry, so a new module is still one file.

2c
Drop the launcher page
Strona główna · you're right, it's a door in front of a door
The rule
Zasada

/ resolves rather than renders. One module installed → redirect to its basePath. Several → redirect to the last one used, remembered in local storage. Nothing installed → the only case that still needs a page, and then it's an onboarding empty state, not a grid of one card.

Switching modules is a job for the rail, not a page you back out to. The "H" mark opens a switcher; ⌘K jumps straight to any destination in any module.

What the launcher was for
Module discovery — now the rail's "+" tile, which opens the same list as a sheet.
A greeting — now the "Today" heading, which greets you with something useful.

What changed
Co się zmieniło
  • One question per screen. The dashboard answers “am I on track” and “what’s next” before anything else.
  • Calmer surfaces. 22px cards, one soft shadow, a single violet accent — macro colours carry all the meaning.
  • Icon rail. Navigation costs 76px instead of a sidebar, and stays put on mobile as bottom tabs.
  • Bilingual labels. English leads, Polish sits underneath at 85% size — no toggle needed.
  • Same token names as your build (surface, border, primary, muted) so this ports back into Tailwind cleanly.
